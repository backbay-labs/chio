# tool-gate Architecture

## Module Boundaries

- `src/lib.rs` owns the guest guard policy and the `#[chio_guard]` entry point.
- The `#[chio_guard]` macro owns the exported WASM ABI: allocator exports,
  request deserialization, return-code encoding, and deny-reason export.
- `chio-guard-sdk` owns the host-compatible `GuardRequest` and `GuardVerdict`
  types. This example should not duplicate ABI serialization logic.
- `crates/chio-wasm-guards/tests/example_guard_integration.rs` owns the
  compiled-WASM host round trip for example guards.

## Pain Points

- The previous implementation put the policy directly in the macro-annotated
  entry function, which made native unit tests cover only a helper rather than
  the same decision path used by the exported guard.
- The deny-list was implicit in a `matches!` arm, so adding or testing policy
  entries required touching evaluation control flow.
- Empty or padded tool names are normalization boundary cases. They should fail
  closed because the guard should not silently canonicalize a tool identifier
  that may be used elsewhere for capability matching.

## Security And API Constraints

- The exported `evaluate(ptr, len) -> i32` ABI generated by `#[chio_guard]` must
  stay unchanged.
- The guard must preserve fail-closed behavior for malformed or ambiguous tool
  names.
- Exact blocked tool names must still deny with the same policy reason.
- Safe, exact tool names must still allow.
- The example must stay `cdylib`-compatible for WASM guard builds and keep
  native `cargo test` useful for guard authors.

## Affected Dependents

- `crates/chio-wasm-guards/tests/example_guard_integration.rs` loads the
  compiled `tool-gate` WASM artifact. It should gain a current-host regression
  for padded tool names so the native policy and host round trip stay aligned.
- No SDK, macro, or host runtime public API change is planned.

## Planned Improvement

Separate policy evaluation from the macro entry point with an explicit
decision model, keep blocked-tool data declarative, add native tests over full
`GuardRequest` verdicts and normalization edge cases, and add a WASM integration
regression for padded blocked names.
