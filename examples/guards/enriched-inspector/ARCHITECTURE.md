# enriched-inspector Architecture

## Module Boundaries

`src/lib.rs` owns the guest guard policy and the `#[chio_guard]` entry point.
The macro owns the exported WASM ABI, allocator exports, request
deserialization, return-code encoding, and deny-reason export.
`chio-guard-sdk` owns the host-compatible `GuardRequest` and `GuardVerdict`
types, so this example must not duplicate ABI serialization logic.
`crates/chio-wasm-guards/tests/example_guard_integration.rs` owns the compiled
WASM host round trip for example guards, and the guard conformance fixture owns
the stable example behavior table.

## Pain Points

The policy currently lives directly in the macro-annotated entry function and
only tests path-prefix matching as a helper. That leaves the actual decision
boundary weakly covered. A `file_write` request with missing path evidence, a
non-canonical `action_type`, or non-normal extracted path data can fall through
as if it were outside the guard's policy instead of being rejected as malformed
host-enriched metadata.

## Security And API Constraints

The exported `evaluate(ptr, len) -> i32` ABI generated by `#[chio_guard]` must
stay unchanged. Host config must still be read through `chio.get_config`, and
native tests must keep working while that host function returns `None`.
Valid requests must keep the current behavior: non-write actions allow, writes
under `/etc` deny, writes under a configured blocked path deny, and writes to
ordinary normalized paths allow. Malformed enriched write evidence should fail
closed instead of being canonicalized in guest code.

## Affected Dependents

`crates/chio-wasm-guards/tests/example_guard_integration.rs` loads the compiled
`enriched-inspector` WASM artifact and should gain host-round-trip regressions
for malformed write evidence and configured-path segment boundaries.
`tests/conformance/fixtures/guard/enriched-fields.yaml` should gain fixture
coverage for the same stable behavior where no host config is required.

## Planned Improvement

Separate policy evaluation from the macro entry point with a small decision
model. Validate optional `action_type` values when present, require normalized
absolute path evidence for `file_write`, preserve segment-aware blocked-path
matching, and add native plus WASM/conformance tests over the full decision
path rather than only the path helper.
