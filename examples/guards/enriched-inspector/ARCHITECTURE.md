# enriched-inspector Architecture

## Module Boundaries

`src/lib.rs` owns the guest guard policy and the `#[chio_guard]` entry point.
The macro owns the exported WASM ABI, allocator exports, request
deserialization, return-code encoding, and deny-reason export.
`chio-guard-sdk` owns the host-compatible `GuardRequest` and `GuardVerdict`
types, so this example must not duplicate ABI serialization logic.
`crates/guards/chio-wasm-guards/tests/example_guard_integration.rs` owns the compiled
WASM host round trip for example guards, and the guard conformance fixture owns
the stable example behavior table.

## Security And API Constraints

The exported `evaluate(ptr, len) -> i32` ABI generated by `#[chio_guard]` must
stay unchanged. Host config must still be read through `chio.get_config`, and
native tests must keep working while that host function returns `None`.
Valid requests must keep the current behavior: non-write actions allow, writes
under `/etc` deny, writes under a configured blocked path deny, and writes to
ordinary normalized paths allow. Malformed enriched write evidence should fail
closed instead of being canonicalized in guest code.

## Affected Dependents

`crates/guards/chio-wasm-guards/tests/example_guard_integration.rs` loads the compiled
`enriched-inspector` WASM artifact for host-round-trip coverage of malformed
write evidence and configured-path segment boundaries.
`tests/conformance/fixtures/guard/enriched-fields.yaml` covers the same stable
behavior where no host config is required.
