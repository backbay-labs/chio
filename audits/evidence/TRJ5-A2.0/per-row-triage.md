# Per-row threat triage

Date: 2026-05-08.

## Scope

Triage every row in `audits/evidence/threats/` (20 files; one per
threat-model row in `spec/security/chio-threat-model.v1.json`) into one
of the four triage tags per `threat-evidence-backfill.md` line 44-68:

- `IMPL-EXISTS-AND-PUBLIC`: cited symbol is `pub fn` (or trait method
  on a `pub` impl) verified in workspace today.
- `IMPL-EXISTS-PRIVATE`: implementation is crate-private; test must
  live in same crate or call through public wrapper.
- `IMPL-PARTIAL`: production stub exists but does not enforce the
  property today.
- `BLOCKED-BY-ARCHITECTURE`: cannot be enforced without non-trivial
  architectural change; deferred.

The plan in `threat-evidence-backfill.md` lines 84-104 provides the
public-symbol claim for each row. This triage VERIFIES each claim via
grep against the workspace at branch HEAD.

## Methodology

For each of the 20 rows:

1. **Symbol existence check**: `grep -nE '^pub (fn|struct|enum|trait|mod) <symbol>'`
   on the cited file path. Pattern also tries `pub fn <name>\b` to
   catch impl methods.
2. **Test body deny-assertion check**: `grep -E 'Verdict::Deny|VerdictDeny|.deny\(|assert.*Err\(|assert.*Reject'`
   on the test file at `crates/chio-conformance/tests/threats/<id>.rs`.
   A `meta-only` result means the file matches the
   `assert_file_contains` or `assert_threat_covered_by_corpus` pattern
   (per Quality Skeptic line 35-37).
3. **Final triage tag** combines both checks: a row tagged
   `IMPL-EXISTS-AND-PUBLIC` is downgraded to
   `IMPL-EXISTS-AND-PUBLIC (test rewrite needed)` if the test body is
   meta-only. The downgrade does NOT change the row's eligibility for
   close (the body rewrite is per-row ticket scope); it is recorded
   so the rewrite work is enumerated.

The triage was generated by `scripts/triage-threat-rows.sh` (added in
the same PR; the script is the reproducible producer of this table).

## Findings

1. **17 IMPL-EXISTS-AND-PUBLIC rows**. All cited symbols verified in
   the workspace at branch HEAD.

2. **2 IMPL-PARTIAL rows**:
   - `resource_exhaustion_dos`: per
     `threat-evidence-backfill.md` line 99, the budget admit path is
     in `chio-kernel`. The cited candidate symbol
     `chio_kernel::dispatch` does not exist as a `pub fn` on
     `crates/chio-kernel/src/kernel/mod.rs` (verified by grep). The
     dispatch entry is internal. **Recommendation**: per the plan,
     this row downgrades to `IMPL-PARTIAL` and either lands a public
     wrapper or defers.
   - `tool_server_escape`: same as resource_exhaustion_dos -
     `chio_kernel::dispatch` is not a public symbol. Per
     `threat-evidence-backfill.md` line 102, this row is expected to
     defer if the tool-server dispatch sandbox enforcement is still
     partial after the `ToolServerConnection` async migration.
     Test body is currently meta-only (per the grep result above).
     **Recommendation**: tag `IMPL-PARTIAL`; the closest companion
     `ssrf_via_http_substrate` (row 16) is `IMPL-EXISTS-AND-PUBLIC`
     and lands.

3. **1 BLOCKED-BY-ARCHITECTURE row**:
   - `wasm_guard_resource_exhaustion`: deferred (depends on
     `wasm-guard SDK v4` which is out of scope). Banner reads
     "<n> of 20 covered, 1 deferred".

4. **Plan correction**: the
   `threat-evidence-backfill.md` line 100 cites `chio_link::HttpEgressContract`
   for row 16 (ssrf_via_http_substrate). The actual public type is at
   `chio_egress_contract::HttpEgressContract` (verified by grep:
   `pub trait HttpEgressContract` at
   `crates/chio-egress-contract/src/lib.rs:15`). The `chio-link`
   crate USES the trait (chainlink, sequencer, pyth) but does not
   define it. This is a plan errata; the row stays
   `IMPL-EXISTS-AND-PUBLIC`, just with the correct crate/path.

5. **Escalation criterion**: escalation fires when
   `IMPL-MISSING + IMPL-PARTIAL + BLOCKED-BY-ARCHITECTURE > 2`.
   Current count: `0 + 2 + 1 = 3 > 2`. **Escalation fires.**
   Reviewer reconsiders the banner; the expected outcome is
   "17 of 20 covered, 3 deferred (resource_exhaustion_dos,
   tool_server_escape, wasm_guard_resource_exhaustion)" rather than
   the plan's earlier estimate of "19 of 20".
