# Hermes signed owner-result recovery

The current cold-installed host candidate made two actual kernel writes. Its
second received receipt was replaced by the first signed receipt. The host
rejected the second result, retaining an unknown operation. The independent
resource observer recorded both originally authorized writes.

A separate operator installation exported the retained exact owner row without
dispatch. A forged signature was rejected with the journal unchanged. Import of
the authentic signed completion verified the original authority, request,
trusted signer, result and delivery proof. It preserved the original unknown
outcome and kept the completion unacknowledged. Explicit result export and
acknowledgement then released the fence. The actual native host read the same
file once; no write was repeated. Export, import and acknowledgement caused zero
resource dispatches. Raw observations and native transcripts are retained here.

The missing-owner-result negative uses an earlier native malformed-response
case: export refused an unknown operation with no retained completion, created
no output and left its journal unchanged. No operator procedure fabricated an
outcome or renewed authority. This is bounded I06/I07 evidence, not full host
acceptance. Artifact identities are in identity.json; no host runtime artifact
was replaced by the new operator-only bridge.
