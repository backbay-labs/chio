\section{Implementation Sketch}
\label{sec:impl}

A substrate that implements the grammar can be built from existing components. The intent of this section is to convince the reader that the grammar is implementable today, not to defend a particular implementation as load-bearing. The implementation is the entry point to the structural argument, not the argument itself.

\paragraph{Components.}
Four substrate components carry the grammar. An admission hook sits between the agent's tool-call message and the tool server's executor: every call passes through it. An action-class registry maps each tool's methods to one of the three classes; the registry is owned by the operator and not by the agent. A rollback executor library implements the inverse operation for each reversible-class method; for destructive-class methods no inverse exists and the host polity's cosignature is required. A receipt log captures the canonical bytes of each admitted call and each emitted rollback receipt, anchored periodically to a tamper-evident log such as a transparency log~\cite{rekor2021}.

\paragraph{The deployment instance.}
A deployment instance of the grammar exists in the endpoint-detection-and-response setting~\cite{programmableSovereignty2026}, where the executive acts are response actions (quarantine, suspend, restrict-egress, terminate). The same admission hook and rollback executor library that govern those response actions can be wrapped around a tool-calling protocol such as the Model Context Protocol~\cite{anthropicMCP2024}. The structural elements are identical: an admission envelope, an action-class taxonomy, a typed rollback witness, a TTL, and (for destructive classes) bilateral cosignature. The endpoint-security instance and the agentic-tool-calling instance differ in the names of the executive acts, not in the grammar.

\paragraph{Worked example.}
Consider an agent that holds a developer credential and is asked to clean up old branches in a GitHub repository. The agent emits a tool call to delete a branch. The admission hook receives the call. The class registry says \texttt{git.branch.delete} is reversible-class: the inverse executor is a branch re-creation from the deleted ref's known commit SHA. The envelope must carry a positive TTL (say, 24 hours) and a rollback receipt slot. The call admits; the branch is deleted; a rollback receipt slot is reserved.

If, within the TTL, the agent's user discovers the branch should not have been deleted, the rollback executor re-creates the branch from the captured SHA and emits a rollback receipt that closes the slot. If the TTL expires without rollback, the call passes from \emph{provisional} to \emph{settled}: the substrate's commitment to keep the rollback slot reservable expires. The receipt log carries both the admission and the rollback (or the unrebuttable settlement) as canonical bytes.

Now consider the same agent asked to delete a customer record from a production database. The class registry says \texttt{db.row.delete-cascade} is destructive-class: no inverse executor exists because cascading-delete-with-backup-prune is not reversible. The envelope must carry the TTL, the rollback slot, \emph{and} a bilateral cosignature from both the operator's polity and the host polity's policy. A scheming model that prompts the operator into approving the call cannot also forge the host polity's independent cosignature; admission fails.

\paragraph{What this section is not.}
This section does not benchmark, evaluate, or measure. The companion substrate's paper carries the structural theorems and the receipt-corpus evaluation. The point here is that an admission hook plus a typed envelope plus a rollback executor library is a small adapter on top of existing tool-calling stacks, not a from-scratch infrastructure. The deployment cost is implementation work, not research work.
