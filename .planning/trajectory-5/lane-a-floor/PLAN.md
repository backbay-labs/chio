This document is the per-sub-lane plan. Each sub-lane below lists scope,

## Evidence Gate close bar (adopted from synthesis)

Per the release work synthesis Lane B language (`00-SYNTHESIS.md` lines 113-114),
each ticket closes with the trio:

- **Enforced call site** in production code (where applicable).
- **Spec / audit citation** identifying the property the evidence pins.
- **Signed evidence artifact**: a real evidence JSON, harness pass, or
  theorem proof, not a placeholder.

Lane A adopts the same close bar with one tightening: a Lane A artifact
qualifies as "real" only when it survives the anti-patterns listed in
`README.md` ("Anti-patterns this lane explicitly refuses"). The
`needs_real_run: true` placeholder accepted by `check-threat-coverage-mutants.sh`
during the bootstrap accommodation is **not** an acceptable close-bar
artifact for any Lane A ticket.

## Sub-lane A5 - Lean4 negotiation_safety against executable model

### Scope

Replace the `rfl`-tautology proof at
`formal/lean4/Chio/Chio/Proofs/HandshakeNegotiation.lean:77-84` with a
refinement-style proof against an executable-model term shared with the
Rust verifier signature.

The current proof:

```
theorem negotiation_safety
    (tokenSchema peerMax : Schema) :
    schemaCeilingCheck tokenSchema peerMax =
      (if Schema.le tokenSchema peerMax then
         CeilingVerdict.admit
       else
         CeilingVerdict.rejectExceedsCeiling) := by
  rfl
```

is rejected by the Quality Skeptic
(`04-quality-verification-skeptic.md` line 52): "is proven by `rfl` -- the
function definition is literally that expression. Tautology proven by
definitional unfolding, not refinement against the Rust verifier."

The fix is structural: define an executable-model term that mirrors the
Rust verifier's actual decision shape (drawn from
`crates/chio-kernel-core/src/capability_verify.rs:226-255`,
`verify_capability_with_negotiated_floor`), then prove `negotiation_safety`
as a refinement statement: any token-schema that the Rust verifier admits
must satisfy `Schema.le tokenSchema peerMax`, and any token-schema rejected
must violate it.

Detailed re-statement and target file paths in `lean4-fix.md`.

### Acceptance

1. `formal/lean4/Chio/Chio/Proofs/HandshakeNegotiation.lean` defines an
   executable-model term `verify_capability_with_negotiated_floor_model`
   (or equivalent) whose signature mirrors the Rust function shape.
2. `negotiation_safety` is re-stated as a refinement theorem against that
   model term.
3. The proof body is **not** `rfl` against `schemaCeilingCheck`'s own
   definition.
4. `formal/theorem-inventory.json` row for `negotiation_safety` carries a
   `status` field of `proven` (replacing the `assumed` state implied by
   the Lean-toolchain disclaimer at file header lines 10-12).
5. The Lean toolchain runs in CI on the chosen lane (existing or new) and
   green-lights the new proof.

### Evidence required

- Diff on `HandshakeNegotiation.lean`.
- Diff on `formal/theorem-inventory.json`.
- One Lean toolchain CI run URL.
- Updated `formal/MAPPING.md` cross-reference between the Lean model term
  and the Rust function.

### Owner-class

Formal-methods engineer.

### Week range

Weeks 6-8.

### Dependencies

- Soft on Lane B's single-entry verifier work (`verify_capability_full`
  becoming the only production entry, per
  `02-protocol-realization-engineer.md` lines 21-25). If Lane B does not
  ship by week 6, A5 still proceeds against `verify_capability_full` as
  it exists today; the refinement proof captures the entry that exists.

## Wave 1 critical-path deliverables (R2 Section 9 patch)

The following Wave 1 deliverables gate Lane A entry into work-ticket
execution. Wave 1 cannot defer them to a later wave:

1. **threat row triage per-row triage** of the 20 threat rows. Each row is
   tagged `IMPL-EXISTS-AND-PUBLIC`, `IMPL-EXISTS-PRIVATE`,
   `IMPL-PARTIAL`, or `BLOCKED-BY-ARCHITECTURE`. The tag is recorded
   as a top-level `triage_status` field in
   `audits/evidence/threats/<id>.json`. R3 escalation criterion fires
   when `IMPL-PARTIAL + BLOCKED-BY-ARCHITECTURE` count > 2 (tightened
   from >4). The runtime gate script checks this field is set.
2. **mutation exclusion audit mutation-exclusion-list audit** of
   `.cargo/mutants.toml`. Each exclusion is marked `OK` or
   `FOR-REMOVAL`. Without this audit, the >=65% target is held against
   a pre-existing exclusion list whose justification has not been
   re-checked.
3. **Kani harness evidence Kani feasibility spike** on each of the 12 proposed
   harnesses (4 per crate). Per-harness wall-clock, peak memory, and
   exit status captured to
   `audits/evidence/Kani harness evidence/local-bound-validation.md`.
4. **release work-A4.2 Apalache encoding feasibility spike** for the bounded
   transitive-closure operator. A 20-line TLA fragment runs against
   Apalache 0.50.x standalone; exit status captured.
5. **TRJ4-033 status confirmation** by Wave 1 reviewer. If TRJ4-033 is
   not closed, A2.7 / A2.9 / A2.13 fail closed and the mobile rows
   ramp later in the lane.

These five Wave 1 deliverables are owned by the Lane A reviewer; their
sign-off is recorded in `reviews/lane-a-wave2.md` (or the
re-rendered Wave 1 review file).
