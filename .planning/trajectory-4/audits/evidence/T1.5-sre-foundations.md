# T1.5 SRE Foundations Evidence

## Implemented

- `crates/chio-metrics-spec/` is the workspace metric-name registry with
  `describe!` descriptors and a golden snapshot test.
- Existing kernel Prometheus metric descriptors now consume registry constants
  for guard, signing-queue, and OTEL drop metrics.
- `deploy/prometheus/` contains recording rules and alert rules for the M01
  SLO surfaces, including receipt-write burn, fail-open suspected, dispatch
  failure, and revocation lag.
- `crates/chio-log-redact/` provides `RedactionLayer` plus `redacted!()`.
- Focused SIEM exporter and kernel warning paths now redact downstream bodies,
  decision reasons, and free-form error strings before operator logs.
- CI calls `scripts/check-sre-metrics-registry.sh` and
  `scripts/check-log-redaction.sh` in the structural gate block.

## Verification Commands

These commands are the focused Lane D gates:

```bash
cargo test -p chio-metrics-spec
cargo test -p chio-log-redact
cargo test -p chio-kernel --test metrics_endpoint
cargo test -p chio-siem
bash scripts/check-sre-metrics-registry.sh
bash scripts/check-log-redaction.sh
cargo fmt --all -- --check
```

## Slips

- Grafana dashboard screenshots and synthetic alert firing are not included in
  this PR. The rule pack is present, but live rendering and alert firing need a
  Prometheus or Grafana test stack.
- The tracing migration is focused on SRE-owned kernel and SIEM surfaces. A full
  89-crate migration should be split into follow-up PRs to avoid crossing lane
  ownership.
