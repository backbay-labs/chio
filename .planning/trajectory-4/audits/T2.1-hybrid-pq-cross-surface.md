# T2.1 - Hybrid PQ end-to-end + cross-surface conformance

**Status**: pending. **Owner**: TBD (federation eng lead).

**Tickets**: TRJ4-200 through TRJ4-207, plus `TRJ4-T2.1.E` Evidence Gate.

## Scope

Hybrid PQ promoted from "designed but not wired" to first-class. Three coordinated changes (round-3 expansion + round-4 algorithm-enum correction):

1. `KernelTrustExchange` accepts a generic `SigningBackend` (today stores a concrete `Keypair`).
2. Capability-token schema adds the `hybrid` enum variant to its `algorithm` field (currently `["ed25519", "p256", "p384"]`); matches `signature.v1.json` which already has the variant. The alg-set string `<classical>+<pq>` lives **inside** the self-describing wire-value pattern `hybrid:<classical>:<pq>:<alg_set>` on `issuer` / `subject` / signature fields, **not** in the algorithm enum.
3. Wire-format encoder/decoder paths treat the hybrid string format as first-class.

Plus cross-surface conformance: T2.1 closes only when the conformance suite passes on **every** advertised surface (MCP wrapped, hosted/native, A2A or HTTP), not just one.

## Acceptance

### Hybrid PQ plumbing

1. **`KernelTrustExchange` generic over `SigningBackend`** (TRJ4-200): today stores concrete `Keypair`; refactor accepts `HybridBackend` instances at the federation layer. Backwards-compatible default keeps Ed25519 for v1 peers.
2. **Capability-token schema adds `hybrid`** (TRJ4-201): `spec/schemas/chio-wire/v1/capability/token.schema.json` `algorithm` enum updated from `["ed25519", "p256", "p384"]` to `["ed25519", "p256", "p384", "hybrid"]`. Matches `spec/schemas/signature.v1.json` and the Rust `SigningAlgorithm` serde shape.
3. **Wire-value patterns updated** (TRJ4-202): `issuer`, `subject`, signature-field regex on the capability-token schema accept the hybrid wire prefix `hybrid:<classical>:<pq>:<alg_set>`. Today those regexes are `^([0-9a-f]{64}|p256:[0-9a-f]{130}|p384:[0-9a-f]{194})$`; T2.1 extends them with the hybrid alternative.
4. **Wire-format encoder/decoder first-class hybrid** (TRJ4-203): capability token, federation handshake envelope, and receipt signing paths all accept and emit the hybrid wire format. Not feature-gated.

### Conformance-tier gating

5. **`Bronze/Silver/Gold` conformance-tier handshake gating** (TRJ4-204):
   - Tier derived from threat-coverage + mutation-kill + Kani harness completeness (data already produced by `chio-spec-codegen::threat_model` + mutants budget).
   - `FederationPeer.conformance_tier` field; bound at handshake.
   - `QuorumPolicy::min_tier` accepted by verifier policy.

### Cross-surface conformance suite

6. **MCP wrapped mode** (TRJ4-205, `chio-hosted-mcp`):
   - Deny receipts emit on rejected tool calls.
   - Lineage class preserved across the wrapper.
   - Revocation propagates from kernel to MCP-bound clients.
   - Budget enforcement is real (no adapter bypass).
   - No adapter bypass for capability/scope/guard checks.
7. **Hosted/native edge** (TRJ4-206, `chio-tower`, `chio-http-core`):
   - Same suite as TRJ4-205, run against the HTTP edge.
8. **A2A or HTTP edge** (TRJ4-207, `chio-a2a-edge` or `chio-acp-edge`):
   - Same suite, run against whichever protocol is in the trj4 promoted set.
   - At least one of A2A or HTTP must be in the suite; both is preferred.

## Evidence Gate (TRJ4-T2.1.E)

Closes only when:

- `spec/PROTOCOL.md` updated with the hybrid PQ wire shape and the conformance-tier semantics.
- `spec/schemas/chio-wire/v1/capability/token.schema.json` algorithm enum and wire-value patterns updated.
- Claim registry: hybrid PQ algorithm and conformance-tier registered.
- Proof manifest updated.
- Theorem inventory updated (signature-correctness theorems extended to hybrid).
- Generated proof report regenerated.
- Cross-surface conformance: deny receipts emit, lineage preserved, revocation propagates, budget enforced, no-bypass attestation across all advertised surfaces. Test fixtures committed at `crates/chio-conformance/tests/cross_surface/`.

## Evidence to capture

- Hybrid signature round-trip: sign with `HybridBackend`, verify with both Ed25519-only verifier (rejects hybrid) and hybrid-aware verifier (accepts).
- Capability-token interop: a v2 token with `algorithm: "hybrid"` and `issuer: "hybrid:<...>"` round-trips through schema validation and signature verification.
- Cross-surface suite: each of MCP wrapped, hosted/native, and A2A/HTTP runs the same fixture set and produces equivalent verdicts and receipts.
- Conformance-tier handshake: `min_tier=Silver` policy rejects a `Bronze`-tier peer at handshake.

## Risks / open questions

- `HybridBackend` performance: ML-DSA-65 sign cost ~200-400us; pair with T2.2 perf profiling work if cache work is in scope.
- Conformance-tier definition: needs explicit thresholds for Bronze/Silver/Gold (e.g., Silver = mutation-kill >= 65% AND threat-coverage >= 90% AND Kani harnesses on >= 4 trust-boundary crates). Lock thresholds in this audit before T2.1 closes.
- Cross-surface conformance scope: the suite has to be small enough to run in CI but comprehensive enough to catch adapter bypass. Target ~50 fixtures per surface; 150 total.
