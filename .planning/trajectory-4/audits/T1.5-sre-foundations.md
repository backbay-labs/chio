# T1.5 - Foundational SRE (mandatory)

**Status**: reopened. The earlier "closed on integrated trj4 branch, with post-review hardening added" claim is retracted by [`../TRAJECTORY-4-CLOSEOUT-ERRATUM.md`](../TRAJECTORY-4-CLOSEOUT-ERRATUM.md); full log-redact migration and observability completeness are covered by Wave 14 of the wave plan. **Owner**: Lane D SRE / observability.

**Tickets**: TRJ4-170 through TRJ4-178.

## Scope

Promoted to mandatory in round-3 because the operability story is the load-bearing non-cryptographic safety property; PHI-in-PagerDuty is the only zero-tolerance failure mode for any healthcare deployment. T1.5 ships the metric taxonomy, burn-rate alerts wired to existing pager routes, and a compile-time log-redaction layer.

## Acceptance

### Metric taxonomy

1. **`chio-metrics-spec` workspace-wide const-string registry** (TRJ4-170): new crate at `crates/chio-metrics-spec/`. Authoritative metric-name registry covering at minimum:
   - `chio_kernel_decision_latency_seconds`
   - `chio_receipt_write_total{outcome}`
   - `chio_guard_evaluations_total{guard,outcome}`
   - `chio_capability_revocation_lag_seconds`
   - `chio_anchor_round_latency_seconds`
   - `chio_federation_hop_total{result}`
   - `chio_dlq_depth{exporter}`
   - Extended with the actual emission sites discovered during TRJ4-172.
2. **`describe!` macro + golden-snapshot CI gate** (TRJ4-171): `cargo test -p chio-metrics-spec` validates that emission sites match the registry. CI fails if any emission site uses a metric name not in the registry, or if the registry has stale entries.
3. **Wire `chio-metrics-spec` into all metric emission sites** (TRJ4-172): refactor `chio-kernel`, `chio-mcp-edge`, `chio-acp-edge`, `chio-a2a-edge`, `chio-http-core`, `chio-anchor`, `chio-federation`, `chio-siem` to use the registry constants.

### Alert pack

4. **Prometheus alert + recording rule pack at `deploy/prometheus/`** (TRJ4-173):
   - Burn-rate alerts (14.4x/1h + 6x/6h dual-window per Google SRE workbook) for each SLO in `docs/operator-runbook/slo.md`.
   - Alert names: `ChioReceiptWriteErrorBudgetBurn1h`, `ChioFailOpenSuspected`, `ChioDispatchFailure`, `ChioRevocationLagHigh`.
5. **Recording rules** (TRJ4-174):
   - `chio:decision_latency:histogram_quantile_p95_5m`
   - `chio:receipt_write_error_ratio_5m`
   - Plus the latency rules for anchor, federation, and guard pipelines.
6. **Alert routes wired to OpsGenie/PagerDuty** (TRJ4-175): existing `chio-siem` integration carries the route.

### Log redaction

7. **`chio-log-redact`** (TRJ4-176): `tracing_subscriber::Layer` runs every log event through receipt's redaction tree. Field-by-field redaction reuses the `chio-data-guards/redactors/default` pattern set.
8. **`redacted!()` macro** (TRJ4-177): rejects raw-string formatting at compile time. Forces every potentially-PHI log site to go through the macro.
9. **Migrate existing `tracing` sites + CI grep-gate** (TRJ4-178):
   - Audit every `tracing::info!`, `error!`, `warn!`, `debug!` site that touches `payload`, `body`, `prompt`, `tool_args`, `tool_output`, `user_message` arms.
   - Migrate to `redacted!()`.
   - CI grep-gate prevents reintroduction of raw `format!`-into-log of those arm names.

## Evidence to capture

- `cargo test -p chio-metrics-spec` validates the metric taxonomy snapshot.
- `deploy/prometheus/chio-recording-rules.yml` and
  `deploy/prometheus/chio-alert-rules.yml` carry the T1.5 rule pack.
- `scripts/check-sre-metrics-registry.sh` blocks unregistered Chio metric names
  in the SRE-owned metric surfaces.
- `cargo test -p chio-log-redact` validates known PHI redaction in both the
  macro path and tracing layer path.
- `scripts/check-log-redaction.sh` blocks raw sensitive log fields in the
  focused kernel and SIEM migration surface.
- Additional closeout evidence is tracked in
  `.planning/trajectory-4/audits/evidence/T1.5-sre-foundations.md`.
- Post-review hardening added missing-data alerts for the receipt-write,
  sidecar, alert-dispatch, and SOC-export counters so burn-rate rules cannot
  silently go green when a producer disappears.
- Post-review hardening expanded `scripts/check-log-redaction.sh` to catch raw
  shorthand fields such as `%error`, `%reason`, `%msg`, `%body`, and
  `%body_text`, and migrated the focused kernel/SIEM violations.

## Risks / open questions

- Some downstream consumers (operator dashboards) may pin metric names; the
  taxonomy crate now publishes a stable v1 set and label new additions clearly.
- `chio-log-redact` may slow down debug-level tracing under high traffic;
  benchmark evidence remains a follow-up before a broad debug-log rollout.
- Existing `tracing` sites are spread across 89 crates; this lane shipped the
  compile-time primitive plus a focused kernel/SIEM migration and grep gate,
  not a repository-wide logging conversion.
