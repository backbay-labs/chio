# T1.2 - Multi-agent receipt DAG + receipt-id migration

**Status**: pending. **Owner**: TBD (protocol eng lead).

**Tickets**: TRJ4-120 through TRJ4-131, plus `TRJ4-T1.2.E` Evidence Gate.

## Scope

Two coupled changes that must ship together:
1. Migrate from kernel-local UUIDv7 receipt IDs to a content-addressed `body_hash` lane while keeping legacy IDs as non-authoritative tooling aliases.
2. Lift `call_chain` from a tree to a DAG with cross-kernel-safe ordering via `dag_ordinal` + HLC.

## Acceptance

### Receipt-id migration

1. **Typed `ReceiptV2BodyHashInput`** (TRJ4-120): struct in `chio-core-types` containing every v2 receipt body field **except** `body_hash`, `signature`, and the legacy UUIDv7 `receipt_id`.
2. **Typed `ReceiptV2SigningBody { body_hash, body }`** (TRJ4-121): `body_hash := H(canonical_jcs(ReceiptV2BodyHashInput))` where `canonical_jcs` is RFC 8785.
3. **`chio-spec-codegen` generates `ReceiptV2BodyHashInput`** from JSON schema (TRJ4-122) so the field set cannot drift.
4. **Sign via `keypair.sign_canonical(&ReceiptV2SigningBody)`** (TRJ4-123) matching the existing `CapabilityTokenBody::sign` pattern at `chio-core-types/src/capability.rs:246-248`. Equivalent ad-hoc byte concatenations are forbidden; verifiers reconstruct the typed struct and re-canonicalize before verifying.
5. **`chio.receipt.v2` schema** (TRJ4-124): contains `body_hash`, `signature`, legacy `receipt_id` (UUIDv7), DAG fields.
6. **Replay-store keys are `body_hash` only** (TRJ4-125):
   - The DAG verifier, replay store, and lineage layer accept and reject only on `body_hash`.
   - Legacy UUIDv7 `receipt_id` stays on the v2 wire as a non-authoritative tooling alias for CLI prefix lookup and explorer surfaces.
   - A tampered legacy `receipt_id` cannot affect replay acceptance because replay never reads it.
   - Index lookups that miss in the alias index fall back to `body_hash` exact match; alias is best-effort.

### DAG and cross-kernel ordering

7. **`dag_ordinal: u64` + HLC `(wall_seconds, logical, kernel_id)` triple per receipt** (TRJ4-126):
   - When a kernel signs a receipt with parents from foreign kernels, it sets `dag_ordinal = 1 + max(parent.dag_ordinal for parent in parent_receipt_ids)` and `(wall_seconds, logical) = max(local_now, max(parent.hlc.advance_logical()))`.
   - Both are signed inputs of the receipt body.
8. **Verifier acyclicity invariant** (TRJ4-127): `child.dag_ordinal > max(parent.dag_ordinal)`. Cross-kernel cycles rejected without requiring a single global clock.
9. **`chio.receipt_lineage_statement.v2`** (TRJ4-128): carries `parent_receipt_ids: Vec<String>` (each is a `body_hash`); canonical sort + dedupe; verifier requires every parent to exist (locally or via a cross-org receipt-join artifact T-10), share a common `chain_id` ancestor, and satisfy the DAG-ordinal acyclicity invariant.
10. **`parent_set_hash`** (TRJ4-129): `parent_set_hash = H(canonical(sort(parent_receipt_ids)))` so a verifier can cheaply check parent-set integrity without walking individual edges.
11. **Lean theorem pinning the body-hash input set** (TRJ4-130): the typed struct field list cannot drift without the Lean proof regenerating.
12. **`AgentLoopBoundsGuard`** (TRJ4-131): `LoopBoundsGuard { max_depth, max_fanout, max_wall_seconds, max_total_subcalls }` reading session journal `tool_sequence`. Per-call-chain `fanout_max` advisory in policy.

## Evidence Gate (TRJ4-T1.2.E)

Closes only when:

- `spec/PROTOCOL.md` updated with the receipt-id migration story, the body-hash input set definition, the `ReceiptV2SigningBody` canonical signing input, and the DAG model.
- `spec/schemas/chio-wire/v1/receipt/v2.schema.json` and `chio.receipt_lineage_statement.v2.schema.json` committed.
- Claim registry: `chio.receipt.v2`, `chio.receipt_lineage_statement.v2` registered.
- Proof manifest: tied to the Lean theorem on body-hash input set and the DAG-acyclicity theorem.
- Theorem inventory updated.
- Generated proof report regenerated.
- Four signed negative-conformance tests:
  - **(a)** v2 receipt where `body_hash` does not match `H(canonical_jcs(ReceiptV2BodyHashInput))` recomputed from wire body fails closed.
  - **(b)** v2 receipt where `body_hash` is recomputed self-referentially (over the wrong field set, including `body_hash` itself or `signature`) fails closed against canonical hash.
  - **(c)** v2 receipt where the legacy `receipt_id` is tampered with but `body_hash` and signature remain valid still verifies (the alias is non-authoritative by design) AND must NOT cause replay confusion (replay keys on `body_hash` only).
  - **(d)** v2 receipt where signature is not `sign_canonical(&ReceiptV2SigningBody)` (e.g. signed only the body or used a different hash function) fails closed.

## Evidence to capture

- v1->v2 migration test: existing v1 receipts continue to verify; v2 receipts verify on the new lane; mixed receipt store works.
- Cross-kernel DAG interop: kernels A and B emit receipts whose parent sets fan in; a verifier with access to both stores accepts the DAG and the acyclicity invariant.
- Replay-store conformance: tampered legacy `receipt_id` on a valid v2 receipt does not poison replay state.
- Lean theorem proof.

## Risks / open questions

- `chio-spec-codegen` cross-file `$ref` limitation may force schema duplication; track as known limitation.
- HLC clock-attestation interaction with adversarial-suite `clock_rewound` cases: ensure existing fixtures still cover the new HLC semantics.
- Kernel-local replay store migration: existing UUIDv7-keyed replay state needs a one-time backfill or alias index.
