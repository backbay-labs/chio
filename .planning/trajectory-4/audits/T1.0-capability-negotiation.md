# T1.0 - Capability negotiation + token versioning (the hinge)

**Status**: pending. **Owner**: TBD (protocol eng lead).

**Tickets**: TRJ4-100 through TRJ4-104, plus `TRJ4-T1.0.E` Evidence Gate.

## Scope

The hinge for all of T1. Without negotiation and a `schema` field on `CapabilityToken`, every additive proposal in T1.1, T1.2, T1.3 forces a flag-day rollout. T1.0 ships the negotiation handshake, schema-tags `CapabilityToken`, defines `chio.capability.v2` reserved fields, and adds the signed-artifact registry/compat gate.

## Acceptance

1. **`chio.capabilities.v1` capability-negotiation handshake** (TRJ4-100):
   - Schema authored at `spec/schemas/chio-wire/v1/capability/capabilities.schema.json`.
   - Envelope encoded/decoded through `chio-federation::trust_establishment`.
   - Peers advertise feature bitset on first handshake; v1.x peers without the field stay on default.
   - Negative conformance: malformed feature bitset fails closed.
2. **`CapabilityToken` schema-tag** (TRJ4-101):
   - `schema` field added to `CapabilityToken` Rust struct in `chio-core-types/src/capability.rs` and the JSON schema at `spec/schemas/chio-wire/v1/capability/token.schema.json`.
   - "Unknown schema" rejected at load time and verify time.
3. **`chio.capability.v1` (current shape, frozen) + `chio.capability.v2` (with caveats, `attenuation_proof`, hybrid PQ)** schemas authored (TRJ4-102):
   - v1 schema is current shape pinned with `additionalProperties: false`.
   - v2 schema has reserved fields for caveats (T1.1), `attenuation_proof` (T1.1), `hybrid` algorithm (T2.1).
4. **Signed-artifact registry / compat gate** (TRJ4-103):
   - Catalog at `spec/schemas/registry.json` listing every signed artifact's schema ID.
   - Load-time check rejects any signed artifact whose `schema` is unknown to the verifier.
   - Verify-time check redundant safety net.
   - Negative conformance: signed artifact with `schema: "chio.capability.v999"` fails closed at both load and verify time.
5. **v1 -> v2 negotiation** (TRJ4-104):
   - `KernelTrustExchange` and `chio-federation` handshake exchange capability-token-version preferences.
   - Peers without `accepts_capability_v2` stay on v1 by default.
   - Mixed v1/v2 federations coexist without breakage.

## Evidence Gate (TRJ4-T1.0.E)

Closes only when:

- `spec/PROTOCOL.md` updated with the negotiation envelope, the `schema` field, and the v1 vs v2 versioning narrative.
- `spec/schemas/chio-wire/v1/capability/{capabilities,token}.schema.json` plus `chio.capability.v1.json` and `chio.capability.v2.json` (or equivalent file layout) committed.
- `spec/schemas/registry.json` lists the new schema IDs.
- Claim registry in `spec/security/` (or wherever it lives) has entries for `chio.capabilities.v1` and `chio.capability.v2`.
- Proof manifest tying claims to evidence updated.
- Theorem inventory updated (any Lean/Coq/TLA+ references to capability-token shape).
- Generated proof report regenerated.
- At least one signed negative-conformance test merged: `chio-conformance/tests/capability_v2_unknown_schema_rejected.rs` (or equivalent).

## Evidence to capture

- Negotiation handshake interop test output (v1 peer + v2 peer, both directions).
- Schema-tag round-trip test for legacy v1 tokens (must continue to verify).

## Risks / open questions

- Some downstream consumers may directly deserialize `CapabilityToken` without checking `schema`; T1.0 must audit and update those call sites.
- `chio-spec-codegen` cross-file `$ref` limitation (typify 0.4.3) may force schema-fragment duplication; document as carry-forward to a codegen split.
