## Explicit verification of integer and algorithm handling

- **Exact integers are supported as written.** Typed signing calls `serde_json::to_value` and the canonicalizer (`crates/core/chio-core-types/src/canonical.rs:119-123`). The number branch checks `as_i64` and `as_u64` before `as_f64` and emits integer decimal digits directly (`crates/core/chio-core-types/src/canonical.rs:276-285`). Consequently `9007199254740993`, signed i64 endpoints, and `18446744073709551615` are preserved, matching the pinned cases in `tests/bindings/vectors/canonical/v1.json:99-116`. The draft expressly identifies the departure from the binary64 I-JSON model, instead of presenting unrestricted RFC 8785 equivalence. This is source and corpus verification, not a newly executed Rust test.

- **Algorithm hint is excluded from signed capability bytes.** `CapabilityTokenBody` plus `CapabilityTokenSigningBody` includes schema/id/issuer/subject/scope/time and present delegation/attenuation/budget members, but neither top-level algorithm nor signature (`crates/core/chio-core-types/src/capability/token.rs:171-198`). New signing uses that schema-aware projection. Schema-less plain-body fallback is conditional (`crates/core/chio-core-types/src/capability/token.rs:243-252,850-864`). The repeated independent Python Ed25519 check verified all 18 corpus cases marked signature_valid over the schema-aware body, and 0 over the recorded schema-less convenience body field.

- **Dispatch and floor admission agree with the draft.** Parsed key/signature variants dispatch verification; mismatched variants fail, hybrids require equal fixed sets and both valid halves (`crates/core/chio-core-types/src/crypto.rs:464-494,1196-1214`). A present hint must match the signature suite; an absent hint does not force Ed25519; a floor then admits its explicit suite set before schema/cryptography (`crates/core/chio-core-types/src/capability/token.rs:813-865`). Output omits absent or Ed25519 hints (`crates/core/chio-core-types/src/crypto.rs:132-141`). Floor-aware verification is distinguished from ordinary signature helpers and from non-strict Ed25519 verification.
