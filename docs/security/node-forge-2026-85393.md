# node-forge GHSA-86w9-cpqp-85rv scope assessment

Date: 2026-10-01. Status: scoped exception for the existing TypeScript peer-test tooling dependency. The owner approved this tooling-only exception on 2026-10-01 after reviewing this assessment.

## Advisory and dependency

[GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv), CVE-2026-85393, affects RSA PKCS#1 v1.5 signature verification in node-forge through 1.4.0. The advisory lists no patched release as of this assessment. It is rated high severity; this assessment does not claim the affected verification code is safe.

The existing `sdks/typescript/package-lock.json` already contains node-forge 1.4.0 before this PR. Its dependency paths are the mobile SDK's Expo peer fixture, through `@expo/cli` and `@expo/code-signing-certificates`. These are Node development/build tools installed to exercise the SDK's Expo peer integration. The lockfile marks this chain as peer dependencies, not as npm devDependencies; the tooling role follows from its actual consumers.

## Workshop release scope

- The Chio CLI and local operator are Rust binaries with their own Cargo lockfiles. They do not consume this npm lockfile.
- The embedded workshop frontend builds from `examples/megastart/frontend/package.json` and its own frozen Bun lockfile. Its build input manifest and assets contain no node-forge dependency.
- The SDK's authored runtime source does not import node-forge. The mobile package exports its authored module and Expo configuration plugin, and does not bundle the Expo CLI into a published SDK tarball.
- The website is built and qualified separately; this exception applies only to the public Chio repository's CVE-monitor scan of the SDK peer fixture. It is not a website vulnerability waiver.

The approved exception allows this workshop release to proceed without presenting a repair to Expo's affected tooling. Developers using that tooling to verify untrusted RSA signatures still need an upstream fix. No claim of unaffected Expo signature verification is made.

## Approved disposition

Add only GHSA-86w9-cpqp-85rv to the existing OSV development-tooling exception list, with this assessment referenced in the reason. Remove the now-unused sharp exception because the relevant dependency locks are patched. Keep new, unrelated advisories blocking.

Remove this exception when an upstream patched node-forge release can be resolved by the Expo tooling. Reassess before adding node-forge to authored runtime code, using Expo code-signature verification as a release trust boundary, adding it to the embedded frontend, or changing the scanned dependency path. The Wasmtime approval in this PR does not authorize this separate exception.
