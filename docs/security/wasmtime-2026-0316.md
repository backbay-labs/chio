# Wasmtime dynamic lifting advisory assessment

Reviewed 2026-10-01 for the CLI workshop release. This assessment is subject to
the CODEOWNERS review required for `deny.toml` changes.

[GHSA-jqpg-j7w6-42pr](https://github.com/bytecodealliance/wasmtime/security/advisories/GHSA-jqpg-j7w6-42pr)
affects dynamically typed component `Val` lifting. Upstream explicitly states
that hosts using `bindgen!` and statically typed APIs are unaffected.

The resolved Wasmtime dependency is consumed by `chio-wasm-guards`:

- `src/host.rs` generates `Guard`, `GuardRequest`, and `Verdict` with
  `wasmtime::component::bindgen!` and registers generated host imports.
- `src/component.rs` instantiates `Guard` and calls its generated
  `call_evaluate` with `GuardRequest`, receiving the generated `Verdict`.
- The core module backend uses the separate core-Wasm value API. It does not
  lift dynamic component records.
- An inventory of Rust source in `crates/` and `examples/` found no dynamic
  `wasmtime::component::Val` consumer.

The advisory exception is limited to RUSTSEC-2026-0316. It does not assert that
Wasmtime 46.0.3 itself is patched. Reassess the exception before adding dynamic
component invocation or another Wasmtime consumer, and remove it on migration
to a patched Wasmtime release. The nearest patched current release, 48.0.3,
requires Rust 1.95; that toolchain migration is separate from this assessment.

The Rustls advisory is addressed by upgrading to 0.23.45, and the yanked DER
0.8.0 package is replaced with 0.8.2. Neither is covered by an exception.
