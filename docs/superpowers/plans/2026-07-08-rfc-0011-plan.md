# Control-plane Replication Soundness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the trust control-plane's homegrown cluster replication protocol (`crates/platform/chio-control-plane/src/trust_control/cluster/`) durable and honest: budget every puller round with strict cursor monotonicity so a replaying peer cannot wedge a node (F15), replace the magnitude-comparison quorum witness with per-origin contiguous replication acks anchored on a durable trusted floor so `quorum_committed` reflects real replication (F16), decouple budget-write handlers from inline cluster syncing behind a background progress watch (F14), and cap status-path materialization and peer-response deserialization (F20).

**Architecture:** The witness (`cluster/deltas.rs:625-661`) currently compares a locally-allocated write seq against each peer's pull cursor (a different sequence domain), so it can witness a single-node write; the pullers (`cluster/deltas.rs:293-527`) trust peer `seq` with no per-round budget or monotonicity guard; each budget-write request drives its own `spawn_blocking(sync_cluster_once)` while polling (`deltas.rs:672-726`); and the status path materializes every store in memory (`cluster/snapshots.rs:55-60,62-137`) while the client deserializes peer bodies uncapped (`service_runtime/client/transport.rs:217,259,290,334`). This plan lands, in the RFC's migration order, D1 (a new `cluster/pull_budget.rs` plus monotone budgeted pullers), D4 (dedicated `MAX(seq)` head reads plus a `read_capped_json` byte cap), D2 (a `budget_import_floors` durable floor table, a gaps-and-islands `budget_ack_heads` store query, per-origin `budget_import_acks` on `PeerSyncState`, and a `BudgetWriteToken`-driven honest witness), and D3 (a `ClusterProgress` watch/notify so the single background loop is the sole driver of cursor and ack advancement). All new code is fail-closed with typed errors and no `unwrap`/`expect`.

**Tech Stack:** Rust workspace crates `chio-control-plane` (axum handlers, `ureq` cluster peer client, `tokio` runtime with `full` features, `std::sync::Mutex<ClusterRuntimeState>`), `chio-store-sqlite` (`rusqlite` budget/receipt/revocation stores, per-node replication seq counter), `chio-cli` (`CliError` with `#[from]` for `serde_json::Error`, `rusqlite::Error`, and every store error). Test infra: standard `#[test]` / `#[tokio::test]` in `cluster_and_reports.rs`; store crate tests return `Result<(), Box<dyn std::error::Error>>`; `proptest` is a workspace dependency (`Cargo.toml` `[workspace.dependencies]` `proptest = "1.10"`) added to this crate's dev-deps in Task 9.

### Known limitations (fail-closed)

- **Election-time liveness wedge (Issue 2) - RESOLVED (codex #965 Finding 1).** `event_seq` is a single store-wide dense sequence, so each authority's events are a sparse subsequence of one global stream, and after a leadership change the new leader's block starts mid-sequence (e.g. `51..`). The original `budget_ack_heads` ran a gaps-and-islands query PARTITIONED BY authority, so a fresh authority's block looked like a per-origin gap (its island `50 != floor 0`) and was dropped, wedging its writes until a snapshot raised the floor. `budget_ack_heads` now computes the GLOBAL contiguous import head H (one gaps-and-islands run over the whole stream, anchored at genesis) and reports, per origin, `MAX(event_seq)` bounded by `H`. Because the budget puller enforces strict global contiguity (Finding 3), holding `H` implies holding every event at seq `<= H`, so a fresh authority whose block sits inside the contiguous prefix is witnessed immediately with no snapshot wait, while a global hole caps `H` and withholds acks above it (fail-closed). Residual: `budget_ack_heads` anchors at genesis, assuming budget mutation events are never bulk-compacted below seq 1 (they are not today); if such compaction lands, anchor at a durable GLOBAL floor instead.
- **Only the budget mutation-event stream is seq-contiguity checked; revocations and receipts are not (codex #965 Finding 2).** The budget mutation-event stream is the only DENSE store-wide sequence (every allocation yields exactly one event), so its puller enforces a cursor-anchored, gap-free GLOBAL guard (`require_contiguous_page` from `cursor + 1`); a forward cursor-jump that would skip unreplicated global seqs is a `PeerProtocolError` that demotes the peer. Tool receipts, child receipts, and lineage are NON-DENSE (`INTEGER PRIMARY KEY AUTOINCREMENT` / plain rowid, written with `ON CONFLICT DO NOTHING` and pruned by retention), so they legitimately contain gaps (rows 1 and 3 with no 2); their pullers use `require_forward_progress` (lowest seq strictly above the cursor + within-page monotonicity) which ACCEPTS a legitimate gap. Revocations use the composite `(revoked_at, capability_id)` advance check (`ensure_revocation_advanced`). For all three non-dense streams (and revocations) a malicious mid-stream skip is NOT reliably client-detectable; the periodic full-state snapshot (`apply_cluster_snapshot`) is the backstop, not incremental convergence. Follow-up: add a dense monotonic seq to the revocation/receipt stores if per-row incremental convergence is required.
- **Budget event_seq gaps from rollback-retry - RESOLVED (codex #965 round-5 P1).** The leader-local rollback-retry path (`existing_event_allowed`) DELETEs the rolled-back authorize and re-appends the same `event_id` under a fresh higher seq, abandoning the original seq. Rather than move the seq (which collides with the shared event/usage counter and follower seq-gated convergence) or a row tombstone (which hits the unique-`event_seq` index on replicas), the abandoned seq is recorded as a METADATA TOMBSTONE (`budget_abandoned_event_seqs`), and `budget_ack_heads` treats a present-OR-abandoned seq as a FILLED slot, so the global contiguous head advances past the hole - no permanent cluster-wide wedge. Soundness: an abandoned seq is never a live write (its write was rolled back / superseded), so it inflates no origin's ack head; a GENUINELY missing event (never recorded abandoned) is NOT filled and still caps the head, so a data-losing node never over-counts. The abandoned set replicates to fresh followers via the snapshot (`budget_abandoned_seqs`) and to delta pullers (`BudgetDeltaResponse.abandoned_seqs`, so the puller tolerates the leader's gappy stream instead of demoting). Recording is at the genuine rollback-retry sites ONLY - `existing_event_allowed` on the leader AND the follower-side REPLACE path (`import_mutation_record_in_transaction`) which records the superseded old seq when it deletes a local `E@X` to install the re-appended `E@Y` - NOT the AFTER DELETE trigger, so a DATA-LOSS delete still caps the head (fail-closed). The follower-replace record closes a wedge for an ALREADY-SYNCED follower whose pull cursor is already past `X` (so the delta's `abandoned_seqs`, which are strictly above the cursor, exclude `X`): it now self-heals immediately rather than waiting for a snapshot. Trust: `abandoned_seqs` on the delta/snapshot wire is peer-provided and trusted at exactly the same level as `mutation_events` - it introduces NO new trust requirement, since a Byzantine peer that could forge `abandoned_seqs` could already forge the mutation events themselves. Residual: the abandoned-seq table grows by one row per rollback-retry (a rare exceptional path); a future compaction of long-passed abandoned seqs (below all peers' cursors) could bound it, but it does not affect correctness.
- **Ack-head cost is incremental, not full-scan (codex #965 round-2 P2).** `budget_ack_heads` runs on every cluster status request (a sync-round interval clamped as low as 50ms), so it maintains the GLOBAL contiguous head against a durable watermark (`budget_ack_head_watermark`) and only advances over rows ABOVE the watermark: steady-state cost is O(new rows), not O(total history). Any DELETE of a mutation event resets the watermark to 0, forcing the next call to re-verify the run from genesis so a hole punched below the watermark can never leave a stale-high head that over-counts (fail-closed). A rollback-retry no longer leaves a permanent hole (resolved above via the abandoned-seq tombstone), so the watermark advances past it and steady-state stays O(new rows).
- **Peer ack heads are replaced, not max-merged (codex #965 round-2 P1).** `update_peer_budget_acks` REPLACES a peer's stored per-origin ack set with its current advertisement so a peer that regressed (restored an older budget DB / lost a prefix) drops its stale higher head and stops witnessing writes it no longer durably holds; a monotone max would let a data-losing peer over-count = double-spend risk.
- **Force-snapshot peers are excluded from witnesses (codex #965 round-3 P1).** `budget_write_quorum_commit_view` additionally requires `!peer_state.force_snapshot`: a peer demoted by a protocol error (or a brand-new peer, which defaults `force_snapshot = true`) carries stale/untrusted acks even after a bare reachability probe flips it Healthy, so it must not witness until its snapshot + delta re-sync clears the flag. Fail-closed quarantine of a protocol-violating peer until it re-syncs; never over-counts.
- **Records-only budget deltas are rejected (codex #965 round-3 P1).** The honest leader emits usage projections only alongside the mutation events they derive from, so `import_budget_delta_response` rejects a page with usage records but no mutation events (`PeerProtocolError::RecordsWithoutMutationEvents`, demote) and advances the global event cursor ONLY from mutation events; a peer can no longer pin the cursor past unimported events via usage `seq`s alone.
- **A per-round pull cap stops the round without demoting (codex #965 round-3 P2).** `PullRoundBudget::charge_page` returns a distinct `RoundLimit` (pages / records / wall-clock), separate from `PeerProtocolError`; the pullers stop the round and resume next sync round while keeping the peer Healthy, so a large but well-ordered backlog (>64 pages) is not mistaken for misbehavior. Only genuine wire-contract violations (gaps, reorders, records-only, oversize) demote.
- **Per-origin ack heads are incrementally maintained (codex #965 round-3 P2).** The follow-on per-origin `MAX(event_seq) GROUP BY authority` no longer scans the full prefix each status call: `budget_ack_heads` folds only the newly-covered rows `(watermark, head]` into a durable `budget_origin_ack_heads` table and reports from it (O(new rows) + O(origins)). A DELETE clears both the watermark and this table (trigger + `reset_budget_ack_head_watermark`), so a hole rebuilds the per-origin heads rather than leaving one stale-high (fail-closed).
- **Budget waiters wake on mid-round acks (codex #965 round-3 P2).** `sync_peer` bumps the `ClusterProgress` tick (`notify_cluster_progress`) immediately after recording each peer's acks, not only at round end, so a write whose quorum is met by one peer's ack does not wait out the timeout while another peer in the same round is slow/unreachable (peer HTTP can block ~15s vs a ~5s wait). The wall-clock timeout remains the backstop and the quorum requirement is unchanged.
- **Waiters also wake after a peer's forced snapshot clears (codex #965 round-4 P2).** A peer's acks are recorded before its snapshot runs while it is still `force_snapshot` (excluded from witnesses); `sync_peer` now bumps the progress tick again right after `apply_cluster_snapshot` clears the flag and after `update_peer_success`, so a write whose quorum is completed by the freshly re-synced peer wakes promptly instead of parking until the next tick while another peer in the round stalls. Wake/latency only; quorum requirement unchanged.
- **Exact write seq even when `eventId` is omitted (codex #965 round-4 P2).** The budget handlers mint a unique event_id (`generated_budget_event_id`: process-local counter + nanos + pid) when the caller omits one and use it for BOTH the write and the witness token, so `budget_write_token` always resolves THIS write's exact `event_seq` by id rather than the authority MAX (which a concurrent same-authority write to another capability can raise, causing a spurious rollback/503). An omitted `eventId` already carried no idempotency guarantee, so minting one changes no retry semantics; the authority-MAX path is now only a defensive fallback (still over-targets, never over-counts).
- **Round budget is checked BEFORE each fetch (codex #965 round-4 P2).** `PullRoundBudget::is_exhausted()` is checked at the top of every puller loop before the next blocking peer fetch, and `sync_peer` runs the streams through a loop that skips the remaining streams once the shared budget is spent, so an exhausted round stops without fetching one page/stream beyond the cap and without spending extra HTTP timeouts that would delay parked writers. Honest-backlog behavior is preserved (stop-without-demote; resume next round).
- **The ack-reset trigger is created once, not on every open (codex #965 round-4 P2).** `ensure_budget_ack_head_reset_trigger` reads `sqlite_master` and only (re)creates the trigger when it is absent or an older single-statement version; steady state does zero DDL, so concurrent budget requests / status polls no longer race a `DROP`/`CREATE` into a "trigger already exists" error or churn schema locks. The one-time upgrade uses idempotent `DROP IF EXISTS` + `CREATE IF NOT EXISTS`, with the manual per-delete-site reset as the belt-and-suspenders backstop.
- **Budget replication is pulled first (codex #965 round-5 P1).** `peer_pullers()` orders the budget pull ahead of revocations/receipts/lineage, so a sustained receipt/lineage backlog cannot spend the shared per-round budget and starve the quorum-critical budget pull (which would leave followers unable to advertise `budget_ack_heads`, timing out HA writes on otherwise-healthy peers).
- **Idempotent budget retries witness under the STORED origin (codex #965 round-5 P1).** `budget_write_token` resolves the seq AND the origin authority from the stored event (`mutation_event_witness_for_event_id`), so a retry of the same `eventId` after leadership moved targets the ORIGINAL authority peers advertise the already-written event under, not the current leader (which would look under the wrong origin and time out a committed write). A null-authority/legacy row or a missing event falls back to the current lease (over-targets, never over-counts).
- **The budget-write wait is sized for serial peer visits (codex #965 round-5 P1).** `budget_write_quorum_commit_timeout` now scales with the peer count and `CONTROL_HTTP_TIMEOUT` (bounded at 120s), so a slow/unreachable peer visited before the peer whose ack makes quorum cannot fire the timeout before the sync loop reaches that peer. A GENUINE partition still returns 503 promptly via the has-quorum check inside the wait loop, so the longer bound only delays the "quorum reachable but a preceding peer is slow" case, never a real partition, and never weakens the quorum requirement.

```rust
use super::*;
use std::time::{Duration, Instant};

pub(crate) const MAX_PULL_PAGES_PER_PEER_PER_ROUND: u32 = 64;
pub(crate) const MAX_PULL_RECORDS_PER_PEER_PER_ROUND: u64 = 200_000;
pub(crate) const PEER_ROUND_WALL_CLOCK_BUDGET: Duration = Duration::from_secs(20);

#[derive(Debug)]
pub(crate) enum PeerProtocolError {
    NonAdvancingPage { after_seq: u64, page_max_seq: u64 },
    PageBudgetExhausted { pages: u32 },
    RecordBudgetExhausted { records: u64 },
    RoundDeadlineExceeded,
    OversizedResponse { cap_bytes: u64 },
    UnattributedBudgetEvent { event_id: String },
}

impl std::fmt::Display for PeerProtocolError {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            Self::NonAdvancingPage { after_seq, page_max_seq } => write!(
                f,
                "peer returned a non-empty page whose max seq {page_max_seq} did not advance past cursor {after_seq}"
            ),
            Self::PageBudgetExhausted { pages } => {
                write!(f, "peer exceeded per-round page budget after {pages} pages")
            }
            Self::RecordBudgetExhausted { records } => {
                write!(f, "peer exceeded per-round record budget after {records} records")
            }
            Self::RoundDeadlineExceeded => write!(f, "peer exceeded per-round wall-clock budget"),
            Self::OversizedResponse { cap_bytes } => {
                write!(f, "peer response exceeded the {cap_bytes}-byte cap")
            }
            Self::UnattributedBudgetEvent { event_id } => {
                write!(f, "peer budget event {event_id} carried no origin authority")
            }
        }
    }
}

pub(crate) struct PullRoundBudget {
    pages_left: u32,
    records_left: u64,
    deadline: Instant,
}

impl PullRoundBudget {
    pub(crate) fn new() -> Self {
        Self {
            pages_left: MAX_PULL_PAGES_PER_PEER_PER_ROUND,
            records_left: MAX_PULL_RECORDS_PER_PEER_PER_ROUND,
            deadline: Instant::now() + PEER_ROUND_WALL_CLOCK_BUDGET,
        }
    }

    /// Charge one page of `records`. Fail-closed: any exhaustion is a peer
    /// protocol error, not a silent stop.
    pub(crate) fn charge_page(&mut self, records: u64) -> Result<(), PeerProtocolError> {
        if Instant::now() >= self.deadline {
            return Err(PeerProtocolError::RoundDeadlineExceeded);
        }
        self.pages_left = self
            .pages_left
            .checked_sub(1)
            .ok_or(PeerProtocolError::PageBudgetExhausted {
                pages: MAX_PULL_PAGES_PER_PEER_PER_ROUND,
            })?;
        self.records_left = self.records_left.checked_sub(records).ok_or(
            PeerProtocolError::RecordBudgetExhausted {
                records: MAX_PULL_RECORDS_PER_PEER_PER_ROUND,
            },
        )?;
        Ok(())
    }
}

/// Strict monotonicity for a `u64` cursor puller. `page_max_seq` MUST be the
/// maximum seq in a non-empty page.
pub(crate) fn ensure_seq_advanced(
    after_seq: u64,
    page_max_seq: u64,
) -> Result<(), PeerProtocolError> {
    if page_max_seq > after_seq {
        Ok(())
    } else {
        Err(PeerProtocolError::NonAdvancingPage { after_seq, page_max_seq })
    }
}

/// Strict monotonicity for the composite `(revoked_at, capability_id)`
/// revocation cursor.
pub(crate) fn ensure_revocation_advanced(
    after: Option<&RevocationCursor>,
    page_max: &RevocationCursor,
) -> Result<(), PeerProtocolError> {
    let advanced = match after {
        None => true,
        Some(prev) => (page_max.revoked_at, page_max.capability_id.as_str())
            > (prev.revoked_at, prev.capability_id.as_str()),
    };
    if advanced {
        Ok(())
    } else {
        Err(PeerProtocolError::NonAdvancingPage {
            after_seq: after.map(|cursor| cursor.revoked_at as u64).unwrap_or(0),
            page_max_seq: page_max.revoked_at as u64,
        })
    }
}

/// Carries the protocol-violation distinction out of the pullers so `sync_peer`
/// can demote a misbehaving peer while leaving a transient failure retryable.
#[derive(Debug)]
pub(crate) enum PullError {
    /// The peer violated the pull wire contract; demote it (fail-closed).
    Protocol(PeerProtocolError),
    /// Transport or store failure; retryable, peer keeps its standing.
    Transient(CliError),
}

impl From<PeerProtocolError> for PullError {
    fn from(error: PeerProtocolError) -> Self {
        Self::Protocol(error)
    }
}

impl From<CliError> for PullError {
    fn from(error: CliError) -> Self {
        Self::Transient(error)
    }
}
```

```rust
/// Fold one puller's result into the round: on success accumulate the applied
/// count; on `PullError::Protocol` demote the peer to Unhealthy (fail-closed,
/// leaves consensus and witness sets); on `PullError::Transient` keep the peer
/// Healthy but record the error. Both error arms short-circuit the round.
fn route_pull(
    state: &TrustServiceState,
    peer_url: &str,
    outcome: Result<u64, PullError>,
    delta_records: &mut u64,
) -> Result<(), CliError> {
    match outcome {
        Ok(count) => {
            *delta_records = delta_records.saturating_add(count);
            Ok(())
        }
        Err(PullError::Protocol(error)) => {
            let message = error.to_string();
            update_peer_failure(state, peer_url, message.clone());
            Err(CliError::cli_other_error(message))
        }
        Err(PullError::Transient(error)) => {
            update_peer_sync_error(state, peer_url, error.to_string());
            Err(error)
        }
    }
}
```

(A demoted (`Unhealthy`) peer is still probed cheaply by `client.cluster_status()` at the top of the next `sync_peer`; a successful probe restores it via `update_peer_reachable` and the next round retries its pulls under a fresh `PullRoundBudget`. Recovery is bounded oscillation, not permanent exile, matching RFC-0011 D1.)

```rust
pub(crate) fn import_budget_delta_response(
    store: &mut SqliteBudgetStore,
    response: &BudgetDeltaResponse,
    current_cursor: Option<BudgetCursor>,
    round: &mut PullRoundBudget,
) -> Result<BudgetDeltaImportOutcome, PullError> {
    if response.records.is_empty() && response.mutation_events.is_empty() {
        return Ok(BudgetDeltaImportOutcome {
            applied_count: 0,
            next_cursor: current_cursor,
            should_continue: false,
        });
    }
    let record_count = response
        .records
        .len()
        .saturating_add(response.mutation_events.len());
    if record_count > BUDGET_DELTA_MAX_RECORDS {
        return Err(PullError::Transient(CliError::cli_other_error(format!(
            "budget delta response contains {record_count} records, maximum is {BUDGET_DELTA_MAX_RECORDS}"
        ))));
    }
    round.charge_page(record_count as u64)?;

    let usage_records = response
        .records
        .iter()
        .map(budget_usage_record_from_view)
        .collect::<Vec<_>>();
    let mutation_records = response
        .mutation_events
        .iter()
        .map(budget_mutation_record_from_view)
        .collect::<Result<Vec<_>, _>>()
        .map_err(CliError::from)?;
    store
        .import_snapshot_records(&usage_records, &mutation_records)
        .map_err(CliError::from)?;

    let previous_cursor_seq = current_cursor.as_ref().map(|cursor| cursor.seq).unwrap_or(0);
    let mut next_cursor = current_cursor;
    for event in &response.mutation_events {
        next_cursor = Some(merge_budget_cursor(next_cursor, budget_cursor_from_event(event)));
    }
    if response.mutation_events.is_empty() {
        for usage in &response.records {
            if let Some(cursor) = budget_cursor_from_usage(usage) {
                next_cursor = Some(merge_budget_cursor(next_cursor, cursor));
            }
        }
    }

    let cursor_advanced = next_cursor
        .as_ref()
        .is_some_and(|cursor| cursor.seq > previous_cursor_seq);
    // Fail-closed: a non-empty page (records or mutation events) that does not
    // advance the merged cursor past the caller's position is a replaying or
    // buggy peer, not a continuation. Drop the old
    // `!mutation_events.is_empty()` escape hatch (RFC-0011 D1, F15).
```

```rust
    serde_json::from_slice(&buffer).map_err(|error| {
```

```rust
    /// Per-origin contiguous ack head: the highest event_seq S from an origin
    /// such that every event in (floor..S] is present with no gap AND the run
    /// reaches down to the durable trusted floor. NOT MAX(event_seq), NOT
    /// anchored on MIN(present). Origins whose lowest present row is above
    /// floor+1 are absent from the result (the caller defaults them to their
    /// recorded floor). This is fail-safe: under-reporting can only withhold
    /// quorum, never grant it (RFC-0011 D2, F16).
    pub fn budget_ack_heads(&self) -> Result<Vec<(String, u64)>, BudgetStoreError> {
        let connection = self.connection()?;
        let mut statement = connection.prepare(
            r#"
            WITH imported AS (
                SELECT
                    bme.authority_id,
                    bme.event_seq,
                    bme.event_seq - ROW_NUMBER() OVER (
                        PARTITION BY bme.authority_id ORDER BY bme.event_seq
                    ) AS island,
                    COALESCE(bif.floor_seq, 0) AS floor
                FROM budget_mutation_events bme
                LEFT JOIN budget_import_floors bif
                    ON bif.authority_id = bme.authority_id
                WHERE bme.authority_id IS NOT NULL AND bme.event_seq IS NOT NULL
            )
            SELECT authority_id, MAX(event_seq) AS ack_head
            FROM imported
            WHERE island = floor
            GROUP BY authority_id
            "#,
        )?;
        let rows = statement.query_map([], |row| {
            let origin: String = row.get(0)?;
            let head = budget_u64_from_row(row, 1, "ack_head")?;
            Ok((origin, head))
        })?;
        rows.collect::<Result<Vec<_>, _>>()
            .map_err(BudgetStoreError::from)
    }
```

(The gaps-and-islands identity: within a partition ordered by `event_seq`, a run incrementing by exactly 1 has constant `event_seq - ROW_NUMBER()`. The run beginning at `floor + 1` has island key `(floor + 1) - 1 = floor`, so `island = floor` selects exactly the prefix anchored at the trusted floor. If the lowest present row is above `floor + 1`, no row lands in the `island = floor` group and the origin is absent. `budget_u64_from_row` is `pub(super)` in `rows.rs:87`, reachable via `super::*`.)

```rust
    /// The durable trusted floor for one origin (0 when none recorded).
    pub fn budget_import_floor(&self, authority_id: &str) -> Result<u64, BudgetStoreError> {
        let connection = self.connection()?;
        let floor: i64 = connection
            .query_row(
                "SELECT floor_seq FROM budget_import_floors WHERE authority_id = ?1",
                rusqlite::params![authority_id],
                |row| row.get(0),
            )
            .optional()?
            .unwrap_or(0);
        Ok(floor.max(0) as u64)
    }

    /// Raise each origin's trusted floor to (min covered event_seq) - 1 for the
    /// events in a freshly installed snapshot. Never lowers a floor. A
    /// puller-introduced gap can never raise the floor because the puller never
    /// calls this; only snapshot install does (RFC-0011 D2).
    pub fn record_budget_import_floors(
        &mut self,
        events: &[BudgetMutationRecord],
    ) -> Result<(), BudgetStoreError> {
        use std::collections::BTreeMap;
        let mut min_by_origin: BTreeMap<&str, u64> = BTreeMap::new();
        for event in events {
            let Some(authority) = event.authority.as_ref() else {
                continue;
            };
            let entry = min_by_origin
                .entry(authority.authority_id.as_str())
                .or_insert(event.event_seq);
            *entry = (*entry).min(event.event_seq);
        }
        let transaction = self
            .connection_mut()?
            .transaction_with_behavior(TransactionBehavior::Immediate)?;
        for (origin, min_seq) in min_by_origin {
            let floor = min_seq.saturating_sub(1);
            transaction.execute(
                "INSERT INTO budget_import_floors (authority_id, floor_seq) VALUES (?1, ?2) \
                 ON CONFLICT(authority_id) DO UPDATE SET floor_seq = MAX(floor_seq, excluded.floor_seq)",
                rusqlite::params![origin, floor as i64],
            )?;
        }
        transaction.commit()?;
        Ok(())
    }
```

```rust
pub(crate) async fn wait_for_budget_write_quorum_commit(
    state: &TrustServiceState,
    write: BudgetWriteToken,
) -> Result<Option<BudgetWriteCommitView>, Response> {
    if state.cluster.is_none() {
        return Ok(None);
    }
    let timeout = budget_write_quorum_commit_timeout(state.config.cluster_sync_interval);
    let poll_interval = Duration::from_millis(250);
    let deadline = Instant::now() + timeout;
    loop {
        let Some(commit_view) = budget_write_quorum_commit_view(state, &write) else {
            return Ok(None);
        };
        if commit_view.quorum_committed {
            return Ok(Some(commit_view));
        }
        if !cluster_consensus_view(state).is_some_and(|consensus| consensus.has_quorum) {
            return Err(plain_http_error(
                StatusCode::SERVICE_UNAVAILABLE,
                &format!(
                    "budget write became leader-visible at commit index {} for authority term {} but cluster quorum disappeared before commit",
                    write.event_seq, write.budget_term,
                ),
            ));
        }
        let sync_state = state.clone();
        match tokio::task::spawn_blocking(move || sync_cluster_once(&sync_state)).await {
            Ok(Ok(())) => {}
            Ok(Err(error)) => warn!(error = %error, "trust-control budget quorum sync failed"),
            Err(error) => warn!(error = %error, "trust-control budget quorum sync task panicked"),
        }
        let Some(commit_view) = budget_write_quorum_commit_view(state, &write) else {
            return Ok(None);
        };
        if commit_view.quorum_committed {
            return Ok(Some(commit_view));
        }
        if Instant::now() >= deadline {
            return Err(plain_http_error(
                StatusCode::SERVICE_UNAVAILABLE,
                &format!(
                    "budget write became leader-visible at commit index {} for authority term {} but only {}/{} quorum witnesses observed before timeout",
                    write.event_seq, write.budget_term, commit_view.committed_nodes, commit_view.quorum_size
                ),
            ));
        }
        tokio::time::sleep(poll_interval).await;
    }
}
```

```rust
impl ClusterProgress {

        Self { tick, kick: tokio::sync::Notify::new() }

}
```

```rust
pub(crate) async fn run_cluster_sync_loop(state: TrustServiceState) {
    loop {
        let sync_state = state.clone();
        match tokio::task::spawn_blocking(move || sync_cluster_once(&sync_state)).await {
            Ok(Ok(())) => {}
            Ok(Err(error)) => warn!(error = %error, "trust-control cluster sync failed"),
            Err(error) => warn!(error = %error, "trust-control cluster sync task panicked"),

        if let Some(progress) = state.cluster_progress.as_ref() {

        }
        match state.cluster_progress.as_ref() {
            Some(progress) => {

                    _ = progress.awaited_kick() => {}
                }
            }
            None => tokio::time::sleep(state.config.cluster_sync_interval).await,
```

```rust
pub(crate) async fn wait_for_budget_write_quorum_commit(
    state: &TrustServiceState,
    write: BudgetWriteToken,
) -> Result<Option<BudgetWriteCommitView>, Response> {
    let Some(progress) = state.cluster_progress.as_ref() else {
        return Ok(None); // not clustered
    };
    let timeout = budget_write_quorum_commit_timeout(state.config.cluster_sync_interval);
    let mut rx = progress.subscribe();
    progress.request_sync();

    let waited = tokio::time::timeout(timeout, async {
        loop {
            let Some(view) = budget_write_quorum_commit_view(state, &write) else {
                return Ok::<_, Response>(None);
            };
            if view.quorum_committed {
                return Ok(Some(view));
            }
            if !cluster_consensus_view(state).is_some_and(|consensus| consensus.has_quorum) {
                return Err(plain_http_error(
                    StatusCode::SERVICE_UNAVAILABLE,
                    &format!(
                        "budget write became leader-visible at commit index {} for authority term {} but cluster quorum disappeared before commit",
                        write.event_seq, write.budget_term
                    ),
                ));
            }
            if rx.changed().await.is_err() {
                return Ok(None); // sender dropped: treat as not-clustered
            }
        }
    })
    .await;

    match waited {
        Ok(inner) => inner,
        Err(_elapsed) => {
            let observed = budget_write_quorum_commit_view(state, &write);
            Err(plain_http_error(
                StatusCode::SERVICE_UNAVAILABLE,
                &format!(
                    "budget write became leader-visible at commit index {} for authority term {} but quorum acks did not arrive before timeout ({}/{})",
                    write.event_seq,
                    write.budget_term,
                    observed.as_ref().map(|v| v.committed_nodes).unwrap_or(0),
                    observed.as_ref().map(|v| v.quorum_size).unwrap_or(0),
                ),
            ))
        }
    }
}
```

(The request path no longer calls `spawn_blocking(sync_cluster_once)`, holds no blocking-pool thread, and cannot hang past `timeout` even if a peer sync spins - F15's failure is contained by Task 2 and this bound. N concurrent writes share the one background loop instead of N sync storms. `budget_write_quorum_commit_view` must be reachable (non-test) here; it is defined in this same module, so it is in scope regardless of the re-export gate.)
