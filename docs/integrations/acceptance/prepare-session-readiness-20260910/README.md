# Prepared-session signer readiness repair

A cold local candidate owner returned from startup before its durable admission
signer file existed. The old preparation helper created an empty session
directory, then failed locally before writing a preparation request or contacting
the kernel. The operator retained that failed directory and owner state. The raw
failure and subsequent real-kernel administrative revocation observations belong
to the companion public harness delivery record.

The repaired helper waits for the selected live owner's trusted signer before
creating a session directory or contacting the bridge. It binds private owner
state, the recorded kernel hash, process executable/UID/command, retained session
database, loopback listener and distinct bootstrap/admin credentials. It refuses
symlinks, hardlinked or writable readiness files, special files, owner changes,
dead processes and expired deadlines. Kernel hashing uses a validated regular
descriptor and deadline checks. Linux uses its actual process executable and
argument data; macOS uses the native process inspection commands.

The signer can persist across a kernel restart. Its availability does not prove
transport readiness. The unchanged authenticated preparation step must still
establish the actual MCP session, scoped authority and credential before success.
No failure automatically retries preparation, clears a journal, or changes an
existing resource/session outcome.

`final-result.json` binds the final source files and 11 passing focused tests
without skips. The native process test runs a tiny Python fixture, not a Chio
kernel or any mandatory agent host. Other cases exercise no-allocation timeout,
late signer publication, wrong owner/hash/listener/PID, file aliases and FIFO
blocking, record changes during final validation, deadline expiration and a
single retained failed preparation. Earlier 10-test source observations remain
separate. The recorded intermediate 11-test failure was fixture state leaking
between independent negative subcases; its fix did not change runtime validation.

The actual cold local successor observation is now retained separately in
`actual-cold-successor/`. The exact repaired helper prepared one session on its
first invocation against the final local static kernel; the owner was then
stopped with durable state retained. No host acceptance, public delivery or new
kernel binary is claimed by this helper repair. The assigned resource-owner README now selects the
explicit local RC provenance and immutable observer image while retaining
publication and final artifact qualification gates.
