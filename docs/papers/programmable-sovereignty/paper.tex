\begin{abstract}
A signed vendor receipt is not sufficient evidence for a buyer to admit a cross-organization agent action: the signature can be valid while the receipt names the wrong treaty, request, outcome, continuation, or receiver policy. We present receiver-owned bilateral admission, a pre-dispatch protocol in which the receiving kernel resolves trust material from its own stores, verifies two distinct configured keys over one canonical DSSE predicate, and checks that the predicate binds the request, outcome, treaty scope, ladder intersection, continuation, lineage, and local and remote receipts. The production Rust hook denies missing, stale, replayed, or mismatched evidence before tool invocation. A companion Lean~4 model gives a strict predicate syntax over a bounded receipt view and proves structural intersection, ladder-floor stability, and sound finite-domain no-widening. An independent Rust reference agrees with the production predicate evaluator over exhaustive atom cases and 1,024 generated cases for each compound property; this is differential alignment, not extraction or whole-runtime verification. On an eight-core Arm server, a deterministic three-vendor SQLite loopback measured full receiver admission at \PSFullAdmissionPFiftySec~s p50 and \PSFullAdmissionPNinetyNineSec~s p99 over \PSPathSampleCount{} release-profile runs. The full pre-dispatch treaty denial path measured \PSPredispatchDenyPFiftyUs~$\mu$s p50 and \PSPredispatchDenyPNinetyNineUs~$\mu$s p99 over \PSCriterionSampleCount{} samples, with the instrumented tool invocation counter unchanged. \PSThreatCaseCount{} named negative cases passed; control of two authorized keys by one actor remains an explicit assumption. We use \emph{programmable sovereignty} only for the resulting local authority over a receipt-admission boundary.
\end{abstract}
