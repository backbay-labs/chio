# Chio editor snippets

This directory holds the tool-neutral snippet source consumed by both
`editors/vscode-chio` and `editors/zed-chio`. Each `*.snippet.yaml`
file validates against `snippet.schema.json` and renders into native
editor formats via:

```bash
cargo xtask snippets regen          # regenerate native files
cargo xtask snippets regen --check  # CI drift check (no writes)
```

The xtask emits two outputs:

- `editors/vscode-chio/snippets/chio.code-snippets` (VSCode native
  JSON; one entry per snippet keyed by `id`).
- `editors/zed-chio/snippets/chio.json` (Zed native JSON; same shape,
  scoped by Zed's lowercase Chio language filename).

Both files carry a `// generated by cargo xtask snippets regen - do
not edit` header so reviewers know to edit the YAML source instead.

## Adding a snippet

1. Add a new `*.snippet.yaml` file with the `id`, `scope`, `prefix`,
   `description`, and `body` keys.
2. Run `cargo xtask snippets regen` and commit both the YAML and the
   regenerated native files.
3. CI runs `cargo xtask snippets regen --check`; the lane fails on
   drift between the YAML source and the native outputs.

## LSP placeholder syntax

`body` entries use the LSP-standard `${1:label}` placeholder syntax so
both editors accept the same source unchanged. Multi-line snippets are
expressed as one body entry per line; the regen pass joins them with
the editor's preferred newline separator.
